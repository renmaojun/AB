# 测试数据补全指引

本文件指导：当用例的"测试数据"小节只给出一部分字段时，如何为增（Create）/ 改（Update）操作补全缺失字段，使表单能通过校验、提交成功，且数据可追溯、可清理。

核心立场：**不凭空想值，先探真实表单再补；补什么、为什么补，全部透明写回用例与报告。**

## 总原则

1. 先探后补。补值之前必须已 `open` 进新建/编辑页并 `snapshot -i`，看清每个字段的类型、是否必填、受限字段的真实可选项。没看到真实表单之前不要臆造任何值。
2. 用户给的优先。用例"测试数据"里已写死的字段，原样使用，不覆盖。
3. 只补必要字段。优先补齐"必填且用户未给"的字段使表单可提交；非必填字段除非用例/预期需要，否则留空或用默认值。
4. 受限字段只取真实选项。下拉、单选、树形、联想选择的值，只能从页面当前真实存在的选项里取，不能填系统不认的字符串。
5. 可造则造，不可造则问。能按类型合理生成的（文本/数字/日期等）直接补；无法凭空生成且必填的（业务图片/附件/依赖外部真实 ID 的关联项）停下来向用户要，不硬凑。
6. 全程透明。补全后的完整字段集写回用例"测试数据"小节；报告里逐字段记录"值 + 来源（用户给定 / 自动补全 / 用户追加提供）"。

## 按字段类型的补全策略

| 字段类型 | 补全策略 | 取证/定位要点 |
|----------|---------|--------------|
| 文本-名称/标题 | 带唯一标记：`AB-TEST-<yyyymmddHHMMSS>`（或用户认可的中文标记）。保证唯一、可检索、可清理 | 用于后续断言"按标记查到/查不到"的锚点 |
| 文本-描述/备注 | 固定可读文案，含标记，如 `AB-TEST 自动化测试数据，可安全删除` | 便于人工辨认 |
| 数字-价格/金额 | 符合格式与边界的合理值（如 `9.90`、`100`）；注意小数位、最小/最大限制 | 读字段旁的校验提示或 placeholder |
| 数字-数量/库存 | 小的正整数（如 `1`、`10`），避开 0 与超大值除非在测边界 | |
| 日期/时间 | 符合格式的合理值；需在"未来/过去"约束内时按约束取（如生效日取今天或明天） | 注意控件是输入框还是日期选择器，后者走点击选择 |
| 下拉 select（原生） | `agent-browser select @eN "<真实选项值或可见文本>"`，取第一个有效业务选项（或用例暗示的那个） | 先从 snapshot/`get html` 读出真实 option |
| 自定义下拉/树形/联想 | 按 complex-widgets 用 `eval` 下探真实可选节点，点选真实存在的项；限定在"当前打开浮层"内 | 不要盲填文本框了事 |
| 单选 radio | `check` 真实存在的某一项，默认取第一个或用例暗示项 | |
| 复选 checkbox | 按用例语义勾选；无要求时勾最少满足必填的项 | |
| 富文本编辑器 | 聚焦后 `keyboard inserttext`/`type` 写入含标记的文本 | 富文本常非普通 input，`fill` 可能无效 |
| 上传-图片/附件 | **不可凭空造业务素材**。若必填且用户未给：停下向用户要文件路径；或询问是否允许用占位图 | `agent-browser upload @eN <path>` |
| 关联项（选已有记录） | 只从真实存在的记录里选；选不到合适的先确认是否需要先造前置数据 | |
| 开关/状态 | 按用例语义设置；无要求时取默认 | |

## 唯一标记规则

所有新建/改写的名称、标题类字段，尽量统一加前缀标记，便于定位与清理：

```
AB-TEST-<yyyymmddHHMMSS>
例：AB-TEST-20261020153012
```

- 时间戳保证同一批多条记录也唯一。
- 若表单校验不允许英文或特殊字符，改用中文标记（如 `自动化测试-20261020153012`），并在报告注明所用规则。
- 一次测试内统一用同一个标记基，断言与清理都以它为锚点。

## 补全后的回写

把补全后的完整字段集写回用例"测试数据"小节，格式示例：

```markdown
## 测试数据
- 起始路径: /product/create
- 商品名称: （用户给定）示例商品
- 商品名称实际写入: AB-TEST-20261020153012 示例商品   # 自动追加唯一标记
- 分类: 家用电器 > 电视                # 自动补全，取自页面真实选项
- 价格: 9.90                          # 自动补全
- 库存: 10                            # 自动补全
- 主图: <需用户提供，必填且无法凭空生成>  # 阻塞项，已回到对齐步骤要用户提供
```

报告"命令轨迹/数据"处同步记录每个字段的取值与来源。

## 与安全红线的衔接

- 补全只负责"填什么值"；"能不能真的提交落库"由 [safety-rules.md](safety-rules.md) 的环境分级与授权决定。
- 生产环境未获授权时：照常完成字段补全并记录，但执行止于"提交前一步"，报告标注"未提交（生产保护）"。
- 自造数据带标记是为闭环清理服务：测后按标记检索删除。
