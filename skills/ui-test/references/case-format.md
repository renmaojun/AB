# 用例格式规范

本文件定义 `test-cases/*.md` 结构化用例的字段规范，以及如何把“测试步骤”翻译成 agent-browser 命令。开始执行前先读本文件校准。

## 文件结构

每个用例是一个 `.md` 文件，由 YAML front-matter（元数据）加若干 `## 小节` 组成。

```markdown
---
用例编号: TC-search-001
模块: 搜索
功能点: 首页关键词搜索
用例标题: 首页搜索框输入关键词后应跳转到搜索结果页并展示相关商品
用例类型: 冒烟
设计技法: 场景法
优先级: P0
version: 1
last-updated: 2026-10-13
---

## 前置条件
- 目标环境可访问（基址见 _ENVIRONMENTS.md，默认 test）

## 测试数据
- 起始路径: /
- 搜索关键词: 电视

## 测试步骤
1. 打开海信商城首页
2. 在页面顶部的搜索输入框中输入搜索关键词
3. 按回车提交搜索
4. 等待搜索结果页加载完成

## 预期结果
- 提交搜索后 URL 应进入搜索结果页（路径包含 search，查询串包含搜索关键词）
- 结果页标题应包含“搜索”
- 结果页应展示与关键词相关的商品（页面可见文本中出现关键词）
```

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| 用例编号 | 是 | 全局唯一，建议 `TC-<模块>-<三位序号>`，用于单条/范围选择与报告追溯 |
| 模块 | 是 | 所属功能模块，用于按模块筛选执行 |
| 功能点 | 是 | 被测的具体功能点 |
| 用例标题 | 是 | 一句话描述验证目标 |
| 用例类型 | 是 | 冒烟 / 功能 / 回归 / 边界 / 异常；用于筛选回归集 |
| 设计技法 | 是 | 等价类 / 边界值 / 场景法 / 错误推测 等 |
| 优先级 | 是 | P0 / P1 / P2 / P3；用于按优先级筛选 |
| version | 是 | 用例版本号，用例内容变更时递增，便于追溯 |
| last-updated | 是 | 最近修改日期 YYYY-MM-DD |

小节：

- 前置条件：执行前必须满足的条件。
- 测试数据：键值对，供测试步骤代入（如 起始路径、搜索关键词、账号）。
  - `起始路径`：以 `/` 开头的相对路径，与环境无关；执行时用 `环境基址 + 起始路径` 拼成完整 URL。环境基址见 `_ENVIRONMENTS.md`。
  - 仅当用例必须固定在某个绝对地址（跨域/第三方）时，才用 `起始地址`（完整 URL）覆盖环境机制。
- 测试步骤：有序列表，只描述“做什么”，不写死元素选择器。
- 预期结果：无序列表，每条是一个可验证的断言点，尽量描述“应观察到什么”，便于取证据。

## 命名与选择约定

- 文件名建议与用例编号一致：`TC-search-001.md`。
- 以 `_` 开头的文件（如 `_TEMPLATE.md`）是模板，不是用例，执行时跳过。
- 编号区间选择按用例编号字符串比较，例如 `TC-search-001..TC-search-003`。
- 元数据筛选按 front-matter 字段精确匹配：`模块` / `优先级` / `用例类型`。

## 测试步骤 → agent-browser 命令映射

测试步骤是意图，执行时按核心循环现场定位元素翻译成命令。常见映射：

| 步骤意图 | 典型命令序列 |
|----------|-------------|
| 打开某页面 | 拼 URL=`环境基址 + 起始路径` → `open <url>` → `wait --load domcontentloaded` → `snapshot -i` |
| 在输入框输入文本 | 从 `snapshot -i` 找到输入框 ref → `fill @eN "<文本>"`（录屏时用 `type` 逐字输入） |
| 点击按钮/链接 | 从 `snapshot -i` 找到 ref → `click @eN`；若新开页面用 `click @eN --new-tab` |
| 提交表单（回车） | `press Enter` |
| 下拉选择 | `select @eN "<值或可见文本>"` |
| 勾选复选框 | `check @eN` / `uncheck @eN` |
| 等待跳转 | `wait --url "**/<pattern>"` 或 `wait --text "<文本>"` |
| 等待元素出现 | `wait @eN` 或 `wait --text "<文本>"` |
| 读取/断言可见文本 | `snapshot` 或 `get text <sel>` |
| 断言 URL | `get url` |
| 断言标题 | `get title` |
| 留证据截图 | `screenshot --annotate results/screenshots/<编号>-<步骤>.png` |

重要规则：

- 每次会导致页面变化的动作之后，先 `snapshot -i` 再做依赖 ref 的下一步。
- 元素找不到或报 “Ref not found” 时，页面多半已变：重新 `snapshot -i` 用新 ref；必要时 `scroll down` 后再 snapshot。
- 点击无效可能是遮挡（弹窗/同意横幅）：snapshot 找到关闭按钮，关闭后 re-snapshot 再重试。
- 自定义输入组件 `fill` 无效时：`focus @eN` 后 `keyboard inserttext "<文本>"`。
- 搜索联想选择框、树形下拉等封装较深的组件（`@eN` 命中包装层导致点了没反应/输入进不去/选了没生效）：按 [complex-widgets.md](complex-widgets.md) 的经验，用 `eval` 下探到内部真实 input 节点聚焦输入、并限定在"当前打开的浮层"内选项。
